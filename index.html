Known limitation: browser tabs get suspended in the background or when the phone is locked, so alarms may not fire reliably while asleep. A production version would need a native wrapper (e.g. Capacitor) so the OS itself triggers the alarm. Use the alarm's Test button to try the full flow now.
Optional

AI coach

Give it your own API key and two things change: the "Congratulations!" line gets written live by a real language model, and the move-challenge music sometimes gets freshly composed instead of picked from the built-in tracks. Skip this entirely and the app works exactly the same, just with the built-in lines and tracks.
How this works, and why it's built this way: your key is saved in this browser's localStorage and is sent directly from your device to the provider's API — it never touches any server of ours and is never written into this project's code or repository. That also means it's visible to anyone who opens this browser's dev tools, which is fine for trying this out yourself but is not how you'd ship this to other people — a real product would route this call through a backend (a Supabase Edge Function, for instance) so the key never lives in the browser at all. Leave this blank and the app falls back to a small set of built-in encouraging lines — nothing breaks either way.
